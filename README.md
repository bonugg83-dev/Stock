# 기계적 리밸런싱 웹앱

TIGER 미국S&P500(360750) · TIGER 미국채10년선물(305080) · 원화 현금, 이 3가지 자산의 목표 비중을 정해두면
분기마다(또는 돈을 넣을 때마다) **몇 주를 사고팔면 되는지 계산해서 보여주는** 웹앱입니다.

- 주문을 대신 넣지 않습니다. 계산 결과만 보여주고, 실제 매매는 직접 합니다.
- **서버 비용 0원**: GitHub Pages(무료 호스팅) + GitHub Actions(무료 자동 실행)만 사용합니다.
- 내 보유 수량·금액은 **내 브라우저 안에만** 저장되고 어디로도 전송되지 않습니다.

> 이 앱은 사용자가 설정한 규칙과 입력값을 바탕으로 포트폴리오 비중과 계산상 조정안을 보여주는 도구입니다. 투자 권유, 수익 보장, 손실 방지를 의미하지 않습니다. 가격·환율·세금·거래 비용 데이터가 실제와 다를 수 있으므로, 실제 거래 전에 사용자가 최신 정보를 직접 확인해야 합니다.

## 처음 한 번만 하는 설정 (약 15분)

### 1) 공공데이터포털 인증키 받기 (ETF 가격용, 무료)

1. https://www.data.go.kr 회원가입 → 로그인
2. "금융위원회_증권상품시세정보" 검색 → **활용신청** (API명 `GetSecuritiesProductInfoService_V2`) (개발계정은 보통 즉시 또는 1~2시간 내 승인)
3. 마이페이지 → 개발계정 → 해당 API의 **일반 인증키(Decoding)** 복사

> 환율(USD/KRW)은 키가 필요 없는 Frankfurter(유럽중앙은행 기준환율)를 씁니다.

### 2) GitHub에 인증키 저장 (코드에 직접 쓰지 않음)

저장소 → **Settings → Secrets and variables → Actions → New repository secret**

- Name: `DATA_GO_KR_KEY`
- Secret: 위에서 복사한 Decoding 키

### 3) GitHub Pages 켜기

저장소 → **Settings → Pages → Build and deployment → Source: GitHub Actions**

### 4) 코드를 main 브랜치에 합치기

작업 브랜치를 main에 병합(Pull Request → Merge)하면 자동으로 데이터 수집과 배포가 실행됩니다.
완료되면 `https://bonugg83-dev.github.io/Stock/` 에서 앱을 열 수 있습니다.
(Actions 탭 → "데이터 수집 및 배포" → **Run workflow**로 언제든 수동 실행 가능)

휴대폰에서는 브라우저 메뉴의 **홈 화면에 추가**를 누르면 앱처럼 쓸 수 있습니다.

## 데이터

| 데이터 | 제공처 | 기준 | 키 |
|---|---|---|---|
| ETF 가격 | 공공데이터포털 금융위원회 증권상품시세정보 (KRX) | **전 거래일 종가** (다음 영업일 오후 공개) | 필요 |
| USD/KRW | Frankfurter (ECB 기준환율) | 영업일 1회 | 불필요 |

- **실시간 가격이 아닙니다.** 실제 주문 전 증권사 앱에서 현재가를 확인하세요.
- 수집은 평일 14:17, 18:17(한국시간)에 자동 실행됩니다. 실패해도 마지막 성공 데이터를 유지하고, 앱에 오류와 데이터 기준일을 표시합니다.
- 키 없이 공식적으로 국내 ETF 시세를 주는 무료 API는 확인되지 않아, 공공데이터포털 키를 사용합니다 (비공식 크롤링은 사용하지 않음).
- 종목코드는 `src/config/assets.json`에서 바꿉니다.
- 키를 받기 전에는 앱의 **설정 → Mock(가상) 데이터**로 모든 기능을 미리 써볼 수 있습니다.

## 브라우저 저장과 백업

기록은 브라우저(IndexedDB)에만 저장됩니다. 브라우저 데이터를 지우면 사라지므로
**설정 → 백업 파일 내려받기**로 가끔 백업하세요. 다른 기기로 옮길 때도 이 파일을 씁니다.

## 기기 간 동기화 켜기 (폰·태블릿·PC가 같은 데이터를 보게 하기)

로그인 없이, 사용자 한 명만 있다고 보고 **Firebase(Firestore) 무료 DB**에 데이터를 저장합니다.
켜면 어느 기기에서든 같은 데이터가 보이고, Chrome이 사이트 데이터를 지워도 다시 열면 복구됩니다.
(브라우저 저장은 그대로 함께 쓰므로 인터넷이 불안정해도 열립니다.)

> 보안 안내: 로그인이 없어서 **프로젝트 ID·API 키와 앱 주소를 아는 사람은 이 데이터를 읽고 쓸 수 있습니다.**
> 자산 정보가 민감하지 않다는 전제의 설정입니다. 걱정되면 설정 → 백업 파일을 가끔 받아 두세요.

### 만드는 방법 (약 10분, 카드 등록 없음)

1. https://console.firebase.google.com → **프로젝트 추가** (Google 애널리틱스는 꺼도 됩니다)
2. 왼쪽 **빌드 → Firestore Database → 데이터베이스 만들기**
   - 위치: `asia-northeast3` (서울), 모드: **프로덕션 모드로 시작**
3. Firestore 화면의 **규칙** 탭 → 안의 내용을 모두 지우고 이 저장소의 `firestore.rules` 내용을 붙여넣은 뒤 **게시**
4. 왼쪽 위 톱니 → **프로젝트 설정 → 일반 → 내 앱 → 웹 앱(`</>`) 추가**
   - 나오는 설정값 중 `projectId`와 `apiKey` 두 개를 복사합니다.
5. 앱에 입력하는 방법은 둘 중 하나입니다.
   - **모든 기기를 한 번에**: 두 값을 `src/config/sync.json`에 넣고 main에 반영 (배포 후 모든 기기가 자동 연결)
   - **기기별로**: 앱 → 설정 → "기기 간 동기화"에 두 값을 입력

### 동작 방식

- 데이터를 바꾸면 몇 초 안에 자동으로 서버에 저장됩니다.
- 다른 기기에서 앱을 열거나 화면으로 돌아오면, 그리고 1분마다 서버를 확인해 새 데이터를 받아옵니다.
- 새 기기에서 처음 열면 첫 설정 화면 대신 서버에 있던 데이터가 바로 나옵니다.
- 두 기기에서 각각 고쳐서 내용이 다르면 "어느 데이터를 사용할까요?" 창이 떠서 직접 고릅니다.
- 한 기기에서 **데이터 초기화**를 하면 서버와 다른 기기도 함께 비워집니다.
- 무료 한도(Spark): 하루 읽기 5만 회·쓰기 2만 회. 1분마다 확인해도 하루 약 1,440회라 개인용으로 충분합니다.

## 계산 규칙 요약

- 주식 수는 정수(1주 단위), 현금은 소수점 원 단위까지 허용, 현금은 절대 음수가 되지 않음
- 금액 계산은 십진수 라이브러리(decimal.js)로 처리해 부동소수점 오차 방지
- 수수료·세금은 원 단위 **올림** (보수적)
- 기본 방식 **현금 우선형**: 팔지 않고 남은 현금 + 추가 납입금으로 부족한 자산만 매수
- **매매형**: 목표보다 많은 자산을 팔고 적은 자산을 매수
- 정수 주 단위 때문에 생기는 오차와 허용 오차(기본 ±5%p)를 함께 표시
- 세금: 일반 계좌 15.4%(국내 상장 해외 ETF 매매차익, 추정), 연금저축·IRP·ISA 0%

자세한 식은 `src/engine/` 폴더의 주석을 참고하세요.

## 개발자용

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm test           # 계산 엔진·수집기 단위 테스트
npm run build      # 타입 검사 + 배포용 빌드 (dist/)
```

```
src/engine/   금융 계산 (화면과 분리, 순수 함수 + 테스트)
src/data/     가격 데이터 형식, Mock 데이터, 불러오기
src/db/       브라우저 저장소 (IndexedDB)
src/ui/       화면
scripts/      GitHub Actions 가격 수집기
```
